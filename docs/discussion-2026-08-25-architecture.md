# Macaronic 架构讨论记录（2026-08-25）

本文为**历史决策记录**；规范性定案见 [architecture.md](architecture.md)，个别表述已被其覆盖（如 Python 缺注解处理、源映射主键、注册表示例语言）。

> 状态：顶层架构、衔接策略（每变量一个文件）、跨块变量自动读写与类型一致性检查、命令行界面、产物目录布局、实现语言（Go）、首批语言（shell+python+go）均已收敛；变量文件格式脚本内自洽。

## 一、定位：构建工具，不是执行器

输入混合语言脚本 → 切分为各语言脚本 → 生成 shell 驱动按期调用各子程序。

```text
foo.mac（混合源文件）
   │ parse：按块标记切分 → [{lang, code}, ...]
   ▼
emit：脚本同目录建临时文件夹，每块一个子目录 + 注入读写 + 驱动脚本
   ├── foo.mac.run/stage1/  (python 块 + 注入的变量读写)
   ├── foo.mac.run/stage2/  (bash 块 + 注入的变量读写)
   ├── foo.mac.run/state/   (跨块变量，每变量一个二进制文件)
   └── foo.mac.run/run.sh   (驱动：保序调用)
```

Bridge 复杂度归零，驱动本身是 shell。两层：切块、拼驱动；块间数据经临时文件夹内 `state/` 目录传递（见第六节），不再依赖 stdout→stdin 管道。

错误定位：任一块失败时，报错映射回 `.mac` 源文件行号——生成 source-map（生成路径+行号为主键、内容哈希为校验），出错后根据报错行反向追踪回源位置，不直接暴露 `<脚本名>.run/stageN/` 下的生成文件。任一块非零退出即停；`state/` 保留现场供排查（下次运行清空）。

## 二、同类工具调研

无确切同款；最接近的是 Org Babel（Emacs，代码块 + `:var` 传结果 + `:session` 会话）、
.NET Interactive（多语言变量共享，2026-04 已归档）、knitr（语言引擎注册表）、
Runme（可执行 Markdown，shell 中心）、marcel（仅 shell+Python 混合交互 shell）。

差异化定位：**脚本文件（非文档/notebook）+ 命令行构建（非交互）+ 块间自动衔接（非手动 export）**。

可借鉴：knitr engine 注册表、org-babel :var 显式传参、.NET Interactive 值级共享。

## 三、块间衔接方式

局限（单一管道）：单一字节流、无结构化、纯文本降级、不可断点重跑、不可分支、错误边界模糊、无法反向通信。

替代（按复杂度升序）：中间文件、环境变量、命令参数、命名管道 FIFO、共享 JSON 文件、unix socket 消息、数据库/消息队列、FFI 嵌入/常驻解释器。

结论：MVP 用「每变量一个文件」作共享状态——`<脚本名>.run/state/<var>`（`<脚本名>.run` 为脚本同目录下的临时文件夹），macaronic 按头部契约表自动为每块注入对该变量的读写（见第六节）；非线性的数据流（任意块可读前面任意块写过的变量）天然成立，「去掉线性」由具名变量达成。第一步升级可考虑共享 JSON 文件/常驻状态；session/kernel 级别不自研，真有需求做 .NET Interactive 格式兼容。

## 四、可衔接的数据类型

MVP 定案：**只支持基本类型**——int / float / bool / str，每个变量一个文件，**二进制编码**。格式脚本内自洽：读写双方均为 macaronic 生成，同脚本内遵循同一约定即可，无需跨脚本/跨版本标准。

struct 类复合类型暂不支持：用户需自行拆分为基本类型变量再声明进契约表，如 `person` 拆成 `person_age = "int"`、`person_score = "float"`。

暂不处理：

- 定长数组（numpy ndarray 即 C 数组布局）
- 需序列化的类型（map/hash/dict、树/图/链表、对象/多态等）

永久边界：函数/身份/资源句柄永远传不了；要传任意类型需 schema/IDL + 代码生成（protobuf/flatbuffers）。

## 五、设计边界（防滑线）

边界在「谁定义计算」：

| 层 | 性质 |
| --- | --- |
| 块切分标注 | 格式约定，非语言 |
| 驱动生成 | Makefile 同类，非语言 |
| 数据契约 schema | 接口定义，非语言 |

危险区：块级控制流（if/loop）、自研类型语义、跨语言对象行为定义——只要有一层进入运行语义就滑向新语言。
硬边界：块间不共享函数/import——每块独立进程，只经 `state/` 传数据，不传代码。单文件：`.mac` 不支持 import 其他 `.mac`。

防滑线：**类型由块代码各自的语言定义，macaronic 只按契约表搬运值（文件读写），不判语义**；控制流留在 shell 驱动里。

## 六、跨块变量传递与类型一致性检查（编译期）

已定案：不做运行时反射，不做静态检查器集成，只做编译期轻量静态检查。

### 数据流由契约表驱动

`head` 区（`#!mac` 块）的 `[contract]` 表是**运行时数据流规范**，不只是检查标签：macaronic 按表为每一块自动注入读写代码（编译期 codegen，不是运行时反射）。

- 注入接口：**同名变量**。块代码直接写 `x`、`y`；生成的 prologue 在块开头从 `<脚本名>.run/state/x` 读入赋给 `x`，epilogue 在块末尾把 `x` 写回文件
- 读写集合由**推断**得出：块内引用的契约变量注入「读」，块内赋值的注入「写」；推断不出的名字不注入（第七节暂停点，运行时由块语言自行报错）
- Python 块内契约变量**必须带类型注解**（`x: int`）供推断，否则 check 报错
- 传输介质：**每变量一个文件**（`<脚本名>.run/state/<var>`，二进制编码），非线性的数据流天然成立——任意块可读前面任意块写过的变量
- 只支持基本类型（见第四节）；struct 由用户拆分为基本类型变量
- 类型映射：契约类型在块语言有对应类型则直接用；无对应类型取最接近类型并警告
- 无类型块（Bash）：以契约表类型为准——其他块声明了类型的变量，Bash 块按其类型读写转换（str↔int/float/bool）
- 遮蔽禁止：块内出现与契约表同名的局部变量 → 编译期报错（见第七节）
- 依赖检查：编译期检查「读未写」——某块读取的变量必须由更早的块写过，否则报错；无初值机制，第一个写者的赋值创建文件。块序**不重排**；并行**推迟**，MVP 只顺序执行。多块写同一变量：顺序多写允许（后写覆盖），**不允许同时写**——写-写依赖强制串行
- 每次运行前清空 `<脚本名>.run/state/`，防止上次运行残留造成假依赖满足

```text
#!mac
[contract]
x = "int"
y = "float"

#!python
print(x)
```

`#!mac` 块的内容是 TOML（标准库 `tomllib` 解析），`[contract]` 表声明跨块变量契约。块标记语法由此统一：所有块都是 `#!lang`，head 只是 lang=mac 的特殊块（声明块，不进入运行管道）。head 块约束：**仅一个、必须位于文件最顶部**。变量命名：必须是所有使用块语言的合法标识符。

### 类型一致性检查

`[contract]` 表是锚点，逐块跑推断（见「块内类型传播」一节），命中表内名字则比对类型，冲突即报错；块内局部变量不要求声明；传播不出即通过。

- 推断种子：显式类型声明（`int x;` 无需初值）、字面量赋值（`x = 5`）、函数返回类型签名——详见「块内类型传播」
- 函数调用赋值：`x = compute()` 若函数有显式返回类型签名 → 解析；无签名或无类型关键字的调用 → 静默通过。`int x = compute()` 由显式声明直接解析（关键字 `int` 定义类型，右值忽略）
- 静态检查器集成（mypy/go types/clang）已排除：原理上只能查单语言单文件，无法跨块，且集成成本高
- 运行时反射已排除：运行时反射需要常驻解释器/反射钩子，违背「编译期完成」；编译期 codegen 注入读写不在此列

## 七、块内类型传播（编译期推断引擎）

**目的**：从变量声明和函数签名中的类型出发，通过替换和简单运算传播类型。传播只在单个代码块内进行，不跨块；其最终产出用于与头部契约表（上一节）比对，以确认跨段变量的类型一致。

把「显式声明」「字面量赋值」「函数签名」统一收敛为一个机制：**符号表 + 顺序求值替换**。

### 机制

维护一张「名字 → 类型」符号表，按语句顺序求值化简：

```text
x: int = 0     → 表 {x: int}
y = x          → 查表 → 表 {y: int}
z = y * 2      → 规则 int ∘ int → int → 表 {z: int}
a = compute()  → 若 def compute() -> int → 表 {a: int}（函数调用点按变量替换，继续传播）
b = a + 1      → int ∘ int → 表 {b: int}
c = unknown_f() → 无签名 → 停，静默通过
```

### 种子（初值来源，三档）

1. 显式类型声明：`int x;` `var x int` `let x: i32` `x: int = 0`
1. 字面量赋值：`x = 5` / `x = 5.0` / `x = "str"` / `x = True`
1. 函数返回类型（签名）：`def f() -> int` / `func f() int` / `int f();` / `fn f() -> i32`

注：Python 块内契约变量必须带类型注解（`x: int`）供推断识别，否则 check 报错；其他语言的显式声明/字面量种子照常。

### 能力边界

| 能 | 不能 |
| --- | --- |
| `y = x` 别名传播 | if/loop 内赋值（控制流不进，留在 shell） |
| `z = y + 1` 同类型运算 | 跨类型运算语义（`int + str` 各语言不同，不判） |
| 链式 `a = b = c` | 函数体推导（只认签名，不认实现） |
| 后写覆盖先写（顺序求值） | 遮蔽（块内与契约变量同名的局部变量 → 编译期报错，不静默） |
| 显式返回类型的函数调用按值替换继续传播 | 无返回签名 / 需要读函数体（如 `def g(): return h()` 链） |
| 有签名的调用参与运算传播（`a + 1`） | 函数参数值类型推导（只有签名，无法推参数内部） |

暂停点：遇到控制流分支 / 跨类型运算 → 停止传播，静默通过（宁可漏报不误报）；同名遮蔽不静默——命中契约表名字即编译期报错。

跨块仍由头部契约表作锚点——本机制是块内的，边界是外部的。

### 与防滑线的关系

符号表 + 替换是「机械替换」，不是「语义解读」：不解释 `+` 的语义、不读函数体、不定义跨语言对象行为。仍在防滑线之内。

## 八、语言支持：核心注册表，不做插件

定案：语言引擎全部内置在核心，用一个注册表（实现语言为 Go，即 Go map）挂接；每个语言一个 handler（类或函数），负责识别声明语法、类型传播规则、生成驱动命令。新增语言 = 新增一个文件 + 注册一行。下文代码块仅为概念示意，非实现语言语法。

首批实现：shell + python + go。

```python
engines = {
    "python": PythonEngine(),
    "shell":  ShellEngine(),
    "go":     GoEngine(),   # 含 build 步骤
}
```

插件/动态加载机制（Python entry-points、Go plugin、子进程协议）全部推迟到出现第三方语言贡献者时再引入——handler 已是注册表，届时包一层入口扫描即可，不返工。

## 九、命令行界面

定案：主命令 `macaronic`，参数为脚本名（`macaronic foo.mac`）；子命令按处理步骤详细拆分：

- 切块（parse）：源文件 → 块列表
- 检查（check）：契约比对 / 类型传播 / 依赖检查
- 生成（build）：块落盘 + 注入读写 + 驱动脚本
- 执行（run）：保序调度子程序
